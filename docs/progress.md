## 3. 次のマイルストーン: M5（辞書の解決規則）

ゴールは「どのファイルにどの辞書が適用されるか」を決めることです。今の `ubiqlint check` は設定ファイルと同じディレクトリの `terms.yaml` を 1 つだけ使うので、プロジェクト内に複数の `terms.yaml` があるときにどれを参照するかが決まっていません。

- 最も近い `terms.yaml` だけを使うか、親の辞書とマージするか、共有カタログをどう持つかは未決です（計画の 8 章）
- M4 で暫定的に決めたこと:
  - `ubiqlint check` は設定ファイルと同じディレクトリの `terms.yaml` を 1 つだけ使う（`--dictionary` で置き換えられる）
  - 検査するファイルは設定ファイルのディレクトリ以下。`.gitignore`・`.ignore`・隠しファイル（`.git` など）は尊重し（git リポジトリの外でも適用する）、シンボリックリンクは辿る。さらに設定ファイルの `exclude`（`include` と同じ glob 作法）に一致するファイルは一切読み込まない
  - `{any}` は空でない単語列にのみ一致する（`get{any}` は `get` だけには一致しない）
  - 同じ識別子に複数のルールが当たったときは、すべてのルールを満たす必要がある
  - 違反メッセージは、動詞チェックだけ緩めても一致する最も近いパターンから組み立てる（`updateOrder` は `{verb}{noun}` に対する `update` の違反として報告される）
  - 違反メッセージの「最も近いパターン」は、動詞チェックだけ緩めた照合で選ぶが、その際は原形の `{verb}` を単語1つに限定する（`{verb}` だけのパターンが識別子全体を飲み込まないように）
  - 定義済みだが活用形の違う動詞は「別の形では定義済みだが `{verb:pp}` は `placed` などを期待」と区別して表示する
  - 「新しい用語・振る舞いなら `terms.yaml` に定義する」というヒントは、パターンに `{noun}` か `{verb}` を含むルールにだけ出す（`get{any}` のようなルールでは逆効果のため）
  - 空の単語列に分割される識別子（`__` など）も、適用されるルールがあれば違反として報告する
  - `{verb}` を結び付ける外側の型は最も内側の名前付きの型（無名クラスは飛ばし、辞書にない名前付きの型は飛ばさない）。後者の場合、結び付けができないことをエラーメッセージで報告する
  - 識別子内に `{noun}` が複数あるときは、最初の `{noun}` の用語に `{verb}` を結び付ける
  - enum 定数と record コンポーネントは `target: field` の対象（plan §4 の target の説明もこれに合わせて更新済み）
  - 1つのファイル内の違反は位置（行・列）でソートして出力する（シンボルの登録順はソース順と限らないため）
  - ソースファイルは UTF-8 のみを読み込む。非 UTF-8 のファイルは `cannot read the file` エラーとして報告し、他のファイルの検査は続ける。そのようなファイルは `exclude` で除外できる
  - 設定ファイルと辞書は両方読み込んでから、エラーをまとめて1回で報告する
  - ディレクトリ走査のエラー（読めないサブディレクトリなど）も報告して失敗させる
  - 出力先のパイプが閉じられても（`| head` など）panic せず、終了コード 1 で終わる

## 4. M6 以降の概要

- **M6 Java のインポート境界ルール**
  - ドメイン層で、ドメイン用語と同じ名前の外部型の `import` と、外部パッケージのワイルドカードインポートを禁止する（計画の 5 章）
  - Java アダプタは、まだ `import` 文を抽出していない。設定ファイルでの書き方も未決
- **M7 辞書を編集するコマンド**: 用語や振る舞いを追加・編集・削除するコマンドを作る。エージェントが辞書ファイルを直接書き換えるのではなく、コマンドを経由して安全に操作できるようにするため。書き込む前に検証し、壊れた辞書や重複した用語ができないようにする。コマンドの体系や、書き換えたときに YAML のコメントや書式を保つかどうかは未決（計画の 8 章）
- **M8 MCP サーバと hooks**: 「ファイルに適用される辞書を返す」と「コード片を検査して違反を候補付きで返す」の 2 つが中心機能。Claude Code の hooks で、編集のたびに検査するループを作る（`exclude` に一致するファイルは対象外にする）
