## 3. M5（辞書の解決規則）で決めたこと

詳しい仕様は[計画の 3.1 節](plan.md#31-辞書の解決規則m5)にあります。

- ソースと同じディレクトリから設定ファイルのディレクトリまで探索し、最も近い `terms.yaml` だけを使う。親や兄弟の辞書とはマージしない
- ルートの辞書は任意。コンテキストごとに同名の用語を別の意味・振る舞いで定義できる。空の辞書も境界になる
- ルールの `include` に一致するソースに辞書がなければ、ソースのディレクトリごとに 1 回だけエラー。不正・読み取り不能な辞書から親へはフォールバックせず、同じ辞書の問題は 1 回だけ報告する。重複抑制は `Reporter` が管理する。他のコンテキストの検査は続ける。ルール対象外のソースには辞書を要求しないが、読み込み・構文エラーは報告する
- `--dictionary` は従来どおり、カレントディレクトリからのパスで全ソースに同じ辞書を適用し、自動解決を無効にする
- 辞書はソースの依存定義なので、辞書ファイル名そのものへの ignore/exclude では境界を消さない。ルート以外ではルール対象のパスから参照される辞書だけ先読みし、ソースの読み込み・構文エラーがあればそのソースに対応する辞書エラーは報告しない
- シンボリックリンクは探索時の見えるパスで辞書を選ぶ。リンク先のパスへは切り替えない
- コアの `resolution` モジュールに `DictionaryResolver` を追加。辞書・不存在・失敗のキャッシュは検査 1 回限りとし、再検査時には作り直す。CLI は解決後に `loaded_dictionary` で共有参照し、`Checker` と索引を辞書のパスごとに使い回す
- 用語追加のヒントと、外側の型が辞書にない診断には、適用した辞書のパスを含める
- `examples/order-service` はルート辞書をパッケージ配下に移し、注文と請求の 2 つの辞書を解決するサンプルに更新した
- 共有辞書の取り込み・合成は未実装。暗黙の継承はせず、明示的な参照のスキーマは今後検討する

## 4. M4 から引き継いだ判定・探索の仕様

- M4 で決めたこと:
  - 検査するファイルは設定ファイルのディレクトリ以下。`.gitignore`・`.ignore`・隠しファイル（`.git` など）は尊重し（リポジトリ内では git と同じ境界でリポジトリ外の `.gitignore` は使わず、tarball 等のリポジトリ外ではツリー内のものだけ適用する）、シンボリックリンクは辿る。さらに設定ファイルの `exclude`（`include` と同じ glob 作法）に一致するファイルは一切読み込まない（ディレクトリを飛ばすのは `legacy/**` のように `/**` で終わる glob の手前部分に一致するときだけで、`src/*` のような glob はディレクトリ名には当てない）
  - `{any}` は空でない単語列にのみ一致する（`get{any}` は `get` だけには一致しない）
  - 同じ識別子に複数のルールが当たったときは、すべてのルールを満たす必要がある
  - 違反メッセージの「最も近いパターン」は動詞チェックだけ緩めた照合で選ぶ。緩めた照合では `{verb}` は 1 語か既知の活用形に一致する単語列しか取らない（`updateOrder` は `{verb}{noun}` への `update` 違反として報告され、`OrderShippingAddress` はパターン一覧のメッセージになる）
  - 定義済みだが活用形の違う動詞は、その振る舞いが期待する形だけを示す（「`{verb:pp}` expects `placed`」の形）
  - 「新しい用語・振る舞いなら辞書に定義する」というヒントは、パターンに `{noun}` か `{verb}` を含むルールにだけ出す（`get` を辞書に定義しても `get{any}` には一致しないため）。M5 で実際に適用した辞書のパスも表示するようにした
  - 空の単語列に分割される識別子（`__` など）はヒントなしの専用メッセージ（「単語を含まない」旨）で違反報告する
  - `{verb}` を結び付ける外側の型は最も内側の名前付きの型（無名クラスは飛ばし、辞書にない名前付きの型は飛ばさない）。後者の場合、結び付けができないことをエラーメッセージで報告する
  - 識別子内に `{noun}` が複数あるときは、最初の `{noun}` の用語に `{verb}` を結び付ける
  - enum 定数と record コンポーネントは `target: field` の対象（plan §4 の target の説明もこれに合わせて更新済み）
  - 1 つのファイル内の違反は位置（行・列）でソートして出力する（シンボルの登録順はソース順と限らないため）
  - ソースファイルは UTF-8 のみを読み込む。非 UTF-8 のファイルは `cannot read the file` エラーとして報告し、他のファイルの検査は続ける。そのようなファイルは `exclude` で除外できる
  - 設定ファイルと、存在するルート辞書（または `--dictionary` の指定辞書）は両方読み込んでから、エラーをまとめて 1 回で報告する
  - ディレクトリ走査のエラーは失敗したパスを先頭にして報告して失敗させる。ただし `exclude` に一致するパスやソースでないファイル（例: リンク先が存在しないシンボリックリンクの README）のエラーは報告しない
  - 検査したソースファイルが 0 件のときは `warning: no source files were checked` を stderr に出す（「違反なし」と区別できるように）。警告は stdout の `path:line:col: error:` 行と混ぜず、終了コードにも影響しない（CI は違反のみで失敗）
  - 出力先のパイプが閉じられても（`| head` など）panic せず、終了コード 1 で終わる

## 5. M6 以降の概要

- **M6 Java のインポート境界ルール**
  - ドメイン層で、ドメイン用語と同じ名前の外部型の `import` と、外部パッケージのワイルドカードインポートを禁止する（計画の 5 章）
  - Java アダプタは、まだ `import` 文を抽出していない。設定ファイルでの書き方も未決
- **M7 辞書を編集するコマンド**: 用語や振る舞いを追加・編集・削除するコマンドを作る。エージェントが辞書ファイルを直接書き換えるのではなく、コマンドを経由して安全に操作できるようにするため。書き込む前に検証し、壊れた辞書や重複した用語ができないようにする。コマンドの体系や、書き換えたときに YAML のコメントや書式を保つかどうかは未決（計画の 8 章）
- **M8 MCP サーバと hooks**: 「ファイルに適用される辞書を返す」と「コード片を検査して違反を候補付きで返す」の 2 つが中心機能。Claude Code の hooks で、編集のたびに検査するループを作る（`exclude` に一致するファイルは対象外にする）
