# 個人利用の準備と将来の配布

当面は個人利用を目的に、GitHub から取得したソースをビルドして使う。
導入手順と、公開に向けて確認した内容を main に反映する。
一般向けの Release 作成、crates.io への登録、ビルド済みバイナリの配布は、
必要になった時点で検討する。

## 1. 公開対象と権利関係の確認

以下は `ab2ce7a4384ba30dabc9bd08400ea89b0c169446` を対象にした初回の確認記録。
公開対象を変更した場合は、その変更も確認する。

- [x] 作者から、vendor の第三者コードを除くコード・辞書・サンプル・文書について、
  公開する権利があることを確認した。
- [x] 本体の [MIT ライセンス](../LICENSE)と各 workspace crate の
  `license.workspace = true` を確認した。Claude Code プラグインも MIT と記載されている。
- [x] 改変して取り込んだ `tree-sitter-java` 0.23.5 には、
  [上流の著作権表示と MIT ライセンス](../vendor/tree-sitter-java/LICENSE)、
  [改変内容と再生成方法](../vendor/tree-sitter-java/README.md)が残っている。
- [x] `cargo metadata --locked --offline --format-version 1` の結果を確認した。
  全ターゲットの registry 依存 164 パッケージに、ライセンスの未記載はなかった。
  MIT、Apache-2.0、BSD-3-Clause、Unicode-3.0、Zlib などのライセンスと、
  選択・組み合わせを指定するライセンス式が含まれる。
- [x] Gitleaks 8.24.3 の標準ルールで、Git 履歴（`git --log-opts=--all`）と
  `git archive HEAD` で取り出したソースを検査し、どちらも検出 0 件だった。
  過去のファイル名にも `.env`、秘密鍵、認証設定などの候補は見つからなかった。
  これは既知パターンによる検査であり、すべての機密情報の不在を保証するものではない。
- [x] サンプルとテストデータは `com.example` 以下の注文・請求の例であり、
  公開する内容として確認した。

MIT ライセンスは ubiqlint 自身のコードに適用する。第三者コードのライセンスと
著作権表示はそれぞれ維持する。特にソースの配布には `vendor/tree-sitter-java`
の LICENSE も含める。ビルド済みバイナリを配布する場合は、組み込む依存に応じて
ライセンス本文・著作権表示・必要な NOTICE を集め、配布物に同梱する。

## 2. 最新版の機能と動作確認

上記コミットには CLI・MCP に加え、診断専用の `ubiqlint lsp` と
Claude Code プラグインが実装されている。LSP は未保存の Java バッファを検査し、
辞書や設定の変更でも再検査する。設定方法とクライアントごとの制約は
[LSP の文書](lsp.md)、MCP の使い方は[エージェントとの連携](agents.md)を参照する。

Linux・Rust 1.99.1 の環境で次を実行し、すべて成功した。
宣言している最小バージョンの Rust 1.88 での再試験は、この確認では実施していない。

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
cargo test --workspace --locked --offline
```

テストは doctest を含め 293 件で、そのうち LSP の結合テストは 16 件。
LSP を子プロセスとして起動し、初期化、未保存バッファの診断、UTF-16/32 の位置、
辞書・設定変更後の再検査、終了処理などを検証している。
この確認では、実際の Claude Code や Neovim に接続する試験は実施していない。

元リポジトリを `git clone --no-local` で別のディレクトリに取得し、空のビルド先と
専用のインストール先を指定して、`cargo install --path crates/ubiqlint-cli --locked --offline`
も実行した。依存パッケージのダウンロードキャッシュは利用した。
インストールした release ビルドで、次を確認した。

- バージョンとヘルプの表示、および README から取り出した設定・辞書・Java コードの検証。
- 正常なコードと order-service サンプルが終了コード 0 になること。
- `place` を `update` に変えると、README に記載した診断が出て終了コード 1 になること。
  必須引数の不足は終了コード 2 になること。
- LSP の初期化、`didOpen` に対する診断、`shutdown` と `exit` による正常終了。
- MCP の初期化、`check_files` に対する診断、入力の終了による正常終了。

README の Git URL から直接インストールするコマンドと、公開後の匿名での取得は、
このローカル clone によるインストール確認とは別に、公開時に確認する。

### クラウド利用向けの追加確認

利用者は Windows の Desktop・Web アプリを使い、コードは GitHub から取得した
クラウドの作業環境で扱う。その前提で、[クライアント別の手順](clients.md)を追加した。
CLI をコードがある実行環境に導入し、追加サーバを登録できる環境では MCP・LSP も利用する。

| 確認対象 | 結果と範囲 |
| --- | --- |
| Claude Code・Mistral Vibe・VS Code の設定例 | JSON/TOML の構文を確認し、例の引数でサーバを起動して独立したプロトコルクライアントから初期化・9 ツールの列挙・サンプルの検査に成功。パスと実行ファイルは確認環境の値に置換した。利用者のアプリからの接続は未確認 |
| Codex CLI 0.167.0-alpha.4 | `mcp get ubiqlint --json` にコマンドラインの設定上書きを渡し、stdio のコマンドと引数を読み込めることを確認。MCP 接続の成功を意味しない |
| Codex app-server からの MCP 接続確認 | 実行環境の読み取り専用ファイルシステムによって app-server の起動に失敗し、未確認。推論やモデルの呼び出しは行っていない |
| GitHub URL と指定 SHA からの直接インストール | 非公開リポジトリの認証で失敗。Cargo 内蔵 Git は HTTP 401、Git CLI を使う場合も認証情報を取得できず失敗した。ソースからのインストール成功とは区別し、公開後に再確認する |

利用者の Claude Code・Codex・Mistral Vibe・VS Code のクラウド設定を変更したり、
各アプリに接続済みと判定したりはしていない。シェルのない URL 登録型コネクタでは、
現在の stdio MCP サーバは直接使えない。

## 3. 個人利用に向けた手順

導入するコミットを固定して、利用するクラウド環境ごとに確認する。

- [x] README に、対応機能、必要環境、インストール、最小の辞書・設定、
  検査例、終了コード、開発中の互換性方針を記載する。LSP と MCP の案内も含める。
- [x] 新しい作業ディレクトリにソースを取得し、README の手順どおりに
  インストールして、正常なサンプルと意図的な違反の両方を確認する。
- [ ] 普段使うクライアントから MCP・LSP を接続し、想定する利用方法で確認する。
- [x] 個人開発としてのサポート方針と、現在の機能・制約を記載する。
  [CHANGELOG](../CHANGELOG.md) は未リリースの記録として管理する。

初回確認時点で GitHub リポジトリは private で、バージョンタグはなかった。
2026-11-10 の main 反映作業時には、リポジトリが public であることを確認した。
この反映作業では公開設定の変更、タグ・Release の作成は行わない。

## 4. 将来、一般向けに配布する場合

一般向けの配布を行うと決めた時点で、次を実施する。

- [ ] 公開対象の最終差分と CI を確認する。機密情報の検査も再実行する。
- [ ] 公開設定を確認し、検証したコミットに `v0.1.0` タグを付け、
  インストール方法を含む GitHub Release を作成する。
- [ ] 公開したリポジトリの URL とタグから、匿名で取得・インストールできることを確認する。

crates.io への配布を追加するときは、内部 crate のバージョン付き依存と公開順序、
ローカル依存かつ `publish = false` の改変版 `tree-sitter-java` の配布方法を決める。
